# Changelog

## 1.0.0-rc.1

First release candidate for the private, single-owner development build. The
interface is in Korean. Automated journeys use local fixtures; the separate
bounded live-provider evidence does not establish general model quality.

### Conversation and members

- Continue one conversation with the Representative and one private conversation
  per admitted member. Ask a short question directly or delegate a checked task.
- Review member proposals before admitting a named member. Follow each task's
  temporary team, steps and challenge exchange without creating extra members.
- Configure explicit model connections and routes. Local login detection alone
  does not authorize execution or demonstrate that an account works.

### Work and checks

- Follow delegated work from the conversation into its progress and expanded
  details. Inspect criteria, steps, evidence and retained results.
- Accept results through an independent check bound to the exact artifact and
  criteria. A conversational answer or challenge concession is not acceptance.
- Create a separate correction task for a known rejection. Keep original results
  and unknown outcomes through restart and supported portable backup/restore.

### Decisions

- Review decisions for lasting effects and permission or checking-rule changes.
- Exercise single-send payment and external-delegation paths with explicit owner
  decisions. An arrival receipt is not an independently accepted result.
- Preserve an uncertain send for inspection instead of resending it after a
  timeout, reload or restart. Fixture journeys are not live payment evidence.

### Apps

- Review declared permissions before installing an app or widening its access.
  Pin installed content and keep app views isolated from the workbench.
- Use supported MCP tool paths with bounded calls. A timed-out write remains
  unknown until explicit reconciliation records evidence; it is not retried.
- App execution depends on the platform sandbox. Linux on Node 24 does not provide
  the required script-app sandbox; installation alone does not make it runnable.

### Budget

- Inspect monthly and per-member token usage and configure an explicit monthly
  output-token limit. These host units are not a provider invoice or currency.
- Keep insufficient-budget work waiting for an owner decision. Preserve unknown
  reservations across restart; time passing alone does not authorize more calls.

### Desktop

- Run the macOS Electron shell with the same authenticated local daemon and
  sandboxed workbench. Closing its window leaves the daemon running; Quit drains
  it. Node 24 and the separate SurrealDB service remain prerequisites.
- Download the unsigned macOS development app and headless install-smoke evidence
  from CI. The smoke inspects an unknown task through the actual packaged app
  against an authenticated fixture daemon, with no live provider calls.
- Developer ID signing, notarization, tagging and publication remain owner steps.
  There is no bundled Node/database installer or automatic update channel.
