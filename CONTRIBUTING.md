# Contributing

Use English for repository artifacts and Conventional Commits. Keep changes reviewable. Do not import archived runtime data or copy abandoned implementation without explicit provenance review.

Run the final candidate's aggregate checks and report passed, failed and not-run stages separately. Fixture evidence is never real-provider evidence. A changed file after testing requires affected checks again. Do not merge, publish credentials, release or deploy as part of a local test.

Follow product ownership boundaries: UI, providers, SDKs and external assistants submit application commands; they do not own Work truth. Persist intent before effects. Unknown outcome is not failure and does not authorize replay. Preserve criteria, artifact versions, identity and authority at evidence boundaries. Never substitute a model's “done” for independent acceptance.

Changes to storage must retain atomic state/event/audit/outbox commit, CAS revisions, command identity readback and backup/restart evidence. Changes to assurance must preserve executor/verifier independence and current-byte verification. Changes to Growth must retain measured evaluation, adoption lineage, later effect and safe revert.

The controlled execution module accepts only known fixture bytes. Do not expand it into an arbitrary code runner or call a CLI agent using platform credentials. Actual providers, external packages, persistent access, VM infrastructure and deployment need their own authorized integration and tests.
