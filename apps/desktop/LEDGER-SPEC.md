# 원장 열 구현 사양과 AAA 채점표

> ## ⚠ 정정 — 이전 회차 비평의 일부는 무효입니다
>
> 이 문서의 초판에 **「Extension Marketplace에 가까워지지 마라」**가 금지 항목으로 적혀 있었습니다. **그것은 오류였습니다.** 헌법 298행은 Massion을 그것으로 «축소»하지 말라는 **제품 범위** 진술이지 시각 어휘 금지가 아닙니다.
>
> **따라서 다음 형태의 지적은 무효이니 실행하지 마십시오:**
>
> - 「이 화면은 VS Code Marketplace / Chrome Web Store / App Store 구조와 닮았다」
> - 「상세 페이지 + 권한 매니페스트 + 출처 표기 3종 세트를 동시에 유지하지 마라」
> - 그 밖에 **레이아웃이 무엇을 «닮았다»는 이유만으로** 내려진 모든 판정
>
> 검증된 UI 형식(상세 페이지·매니페스트·목록·트리·탭·체크리스트)은 **목적에 맞으면 쓰십시오.** 낯선 조작을 발명해 피하지 마십시오 — 이 문서의 「정보 구조는 새롭게, 조작은 흔하게」와 정면으로 충돌합니다.
>
> **살아 있는 지적**은 그 화면이 무엇으로 «끝나는가»에 대한 것입니다. 예를 들어 확장 표면의 진짜 결함은 매니페스트를 쓴 것이 아니라, 부여된 역량이 조직에서 실제로 무엇을 하는지로 이어지지 «않는» 것입니다. 그 지적은 유효하니 해소하십시오.
>
> 죽은 공간·정렬 축·글리프 오용·원장 부재 같은 지적(A·C 계열)은 전부 그대로 유효합니다.

이 문서는 두 독자를 위한 정본입니다.

- **구현자**(codex, gpt-5.6-luna xhigh) — 무엇을 만들지
- **검수자**(비평 에이전트) — 무엇을 기준으로 통과·실패를 가릴지

채점표 항목은 전부 **스크린샷 한 장만 보고 통과/실패를 가릴 수 있어야** 합니다. 「아름다운가」처럼 판정 불가능한 항목은 넣지 않습니다. 그래야 루프가 수렴합니다.

## 1. 무엇을 만드는가

모든 표면 오른쪽에 **원장(Ledger) 열**을 붙입니다. 표면 구조는 바꾸지 않습니다.

원장은 «지금 보고 있는 대상에 귀속된 사건»이 시간 역순으로 쌓이는 열입니다. Work를 보고 있으면 그 Work의 사건, 조직 노드를 보고 있으면 그 노드의 사건입니다.

### 왜 이것인가

경쟁 도구 12종이 구조적으로 못 그리는 것이 이것입니다. 그들에게는 담을 필드가 없습니다. 우리에게는 DB 제약으로 실재합니다.

- `work_verification.assurance_run_id` → `verifier_handle`은 문자열이 아니라 `organization_node.handle`이고, DB가 저장 시점에 그 노드가 `status='active'`인지 확인하고 아니면 THROW합니다(`packages/work/src/schema.ts:402-405`).
- `packages/assurance/src/independence.ts:13-35`가 contributor 집합을 계산해 실행 기여자가 최종 verifier가 되는 것을 막습니다. **「분리」가 UI 문구가 아니라 계산된 사실입니다.**
- `assurance_check.executor_execution_id` → `runtime_execution` → `route_attempt.execution_id` → `model_profile_id`로 「왜 이 모델이었나」까지 이어집니다.

### 원장 줄 하나의 구조

```
[시각 11px mono] [주체색 2px 좌측 레일] [무엇을 했나 11px] [메타 10px] [› 문]
 10:24            ▌Iris             판정 막힘 1            실행 기여자 아님 · 기준 4   ›
```

- **시각**은 우측 정렬 tabular-nums. 같은 분이면 반복하지 않고 비웁니다.
- **좌측 2px 레일**은 사건 주체의 색입니다(`--agent-0`~`--agent-7`). 사람 사건은 무채.
- **각 줄은 다음 마디로 가는 문입니다.** 클릭하면 그 대상으로 이동합니다. 문이 없는 줄에는 `›`를 그리지 않습니다.

## 2. 사슬 — 원장이 이어야 하는 여섯 마디

원장의 존재 이유입니다. 각 마디는 클릭으로 다음 마디에 도달해야 합니다.

| # | 마디 | 화면이 답해야 하는 것 | 계약 |
|---|---|---|---|
| 1 | 요청 | 누가 무엇을 요청했나 | `work.summary` |
| 2 | 배치 | 조직이 누구를 붙였나, 조직 버전은 | `work.detail`, `organization.graph.snapshot` |
| 3 | 실행 | 누가 실행했고 무엇을 썼나 | `runtime.execution.subscription-lineage` **(등록됨 · 호출 0회)** |
| 4 | 판정 | 누가 판정했고 실행자와 분리됐나 | `work.verifications` **(criteria 실림 · 화면이 버림 → 수정 완료)** |
| 5 | 개선 | 이 판정이 무슨 개선을 낳았나 | `growth.*` |
| 6 | 효과 | 채택 후 나아졌나 | `growth.effect.*` |

**3번과 5·6번이 아직 화면에 없습니다.** 3번은 계약이 이미 등록돼 있고 데스크톱 호출이 0회라 **백엔드 작업 없이** 붙습니다.

## 3. 시각 규칙 (「원장」 세계)

토큰은 `apps/desktop/src/styles.css`에 이미 적용돼 있습니다. **하드코딩 색 금지 — 반드시 토큰을 쓰십시오.**

### 색

| 용도 | 토큰 | 값 |
|---|---|---|
| 캔버스 | `--bg-0` | `#0b0c0e` |
| 레일·목록·원장 바닥 | `--bg-1` | `#15171a` |
| 패널·블록 | `--bg-2` | `#1b1d20` |
| 팝오버·다이얼로그 | `--bg-3` | `#202225` |
| 컨테이너 안쪽 분절 | `--line` | `#2b2d30` |
| 열 seam·헤더 하단 | `--line-strong` | `#3a3c3f` |
| 열린 대상의 제목 **하나** | `--fg` | `#f4f5f7` |
| **본문 기본값** | `--fg-2` | `#c8cdd6` |
| 보조 | `--fg-3` | `#a2a8b4` |
| 반복 메타(시각·checksum·상태어·카운트) | `--fg-4` | `#838993` |
| 사람이 필요함 | `--gate` | `#f0bc4b` |
| 실행이 막힘 | `--halt` | `#f5766e` |
| 긴급 정지 | `--emergency` | `#e8442e` |

- **위계는 크기나 웨이트가 아니라 이 네 단계가 만듭니다.**
- `--fg`는 열당 최대 1회. 본문은 `--fg-2`.
- 초록은 없습니다. 완료를 초록으로 칠하지 마십시오.
- 주체색 8개는 아바타·이름·원장 좌측 레일·진행 막대 네 곳에만. 버튼·테두리·배경 금지.

### 타이포 (Pretendard, 한글 보정 포함)

| px / line-height / 자간 / weight | 용도 |
|---|---|
| 11 / 16 / 0 / 400 **Geist Mono** | checksum·경로·핸들·revision·시각. **라틴·숫자 전용, 한글 금지** |
| 12 / 18 / 0 / 400 | 조밀 메타, 카운트 |
| **13 / 20 / -0.005em / 400** | **본문 기본.** 리스트 행 라벨, 메시지, 섹션 헤더 |
| 14 / 21 / -0.006em / 400 | 산문 밀도 |
| 15 / 24 / -0.008em / 600 | 표면 제목 |
| 17 / 26 / -0.012em / 600 | 상세 제목 |
| 20 / 28 / -0.018em / 600 | 방 제목 |

- **10px 금지.** 한글이 안 읽힙니다.
- **양수 자간 금지.** 한글엔 대문자가 없어 음절 결합만 깨집니다.
- 웨이트 3스톱만: 400 / 500 / 600. 13px 강조는 500까지, 600은 15px 이상에서만.
- 숫자는 `tabular-nums`.

### 간격

- **행 30px, 행 간 gap 2px, 피치 32px.** 세로 치수는 32의 배수나 16에 정합.
- 행 내부 좌우 패딩 8px, 아이콘–라벨 gap 8px, 반경 **4px**.
- **행은 한 줄입니다.** 2줄 행을 만들지 마십시오.
- 들여쓰기 한 단계 = 32px.
- 헤더 밴드 48px, 모든 열 동일.
- 원장 열 폭 **320px**. 1360px 미만에서 접을 수 있게 하되 기본은 열려 있습니다.

### 표면 처리

- 헤어라인 **0.5px**. macOS Retina 전용이라 실제 1 device px입니다.
- **반경은 4px과 원형 둘뿐.** 태그·컨트롤·패널마다 다른 반경 금지.
- 인라인 그림자 없음. 팝오버·다이얼로그에만.
- **리스트 행 구분선 0개.** 32px 피치와 호버 채움이 분절을 담당합니다.
- 선택 = 흰색 4.7% 채움, 테두리 없음. 호버 = 2.7%.
- 포커스 = 1px 실선 `--fg`, offset 2px, 전역 하나. 컴포넌트별 ring 유틸 금지.
- **기본값은 그리지 않습니다.** 「할 일」·「미지정」·「담당 없음」이면 셀을 비웁니다.
- **카운트는 배지가 아닙니다.** 라벨 뒤 한 칸 띄운 같은 크기 `--fg-4` 숫자. 원형·필·색 배경 금지.

### 상태 글리프

색이 아니라 **14px 글리프**가 상태를 인코딩합니다.

- 미시작: 빈 원 0.5px 외곽 — 또는 아예 안 그림
- 진행: 부분 채움 원, **채움 각도 = 실제 진척률**
- 완료: 채운 원 `●`
- **검증 완료: 채운 원 + 0.5px 외곽 링 `◉`**
- 게이트 `◇` = gate색, 차단 `⊘` = halt색

**완료와 검증 완료가 같은 모양이면 안 됩니다.** 「완료는 선언이 아니라 검증이다」가 이 제품의 주장입니다.

### 모션

- 호버 fade-in **0ms** / fade-out **150ms**
- 일반 전이 100ms, 큰 전이 220ms, `cubic-bezier(0.2, 0, 0, 1)`
- **원장 append**: opacity 0→1 **120ms** + 주체색 점 밝기 1.6배→원복 200ms 1회. **레이아웃 이동 없음.**
- 막대는 `250ms linear` — ease를 넣으면 중간 프레임이 실제 값과 달라집니다
- 스피너·스켈레톤 셰이머·펄스·글로우·숫자 카운트업 **금지**
- `prefers-reduced-motion`에서 전부 0ms, 원장 fade만 유지

## 4. AAA 채점표 — 검수자용

**스크린샷 한 장만 보고 판정하십시오.** 소스를 읽지 마십시오. 사용자는 소스를 안 읽습니다.

### A. 크래프트 (14항목)

| # | 항목 | 통과 조건 |
|---|---|---|
| A1 | 죽은 공간 | 콘텐츠 없는 영역이 화면의 **15% 이하** |
| A2 | 위계 | 명도 단계가 **3단 이상** 실제로 구분됨 |
| A3 | 정렬 축 | 세로 정렬선이 **3개 이하**. 들쭉날쭉한 좌측 시작점 없음 |
| A4 | 행 리듬 | 리스트 행 피치가 **일정**. 2줄 행 없음 |
| A5 | 구분선 | 리스트 안 가로선 **0개** |
| A6 | 반경 | 화면 전체에서 반경이 **4px과 원형 둘뿐** |
| A7 | 10px | 10px 이하 텍스트 **0개** |
| A8 | 자간 | 한글에 벌어진 자간 **0곳** |
| A9 | 배지 | 원형·필 카운트 배지 **0개** |
| A10 | 초록 | 초록 계열 **0곳** |
| A11 | 노랑 | 노랑이 「사람이 필요함」 외에 **0곳** |
| A12 | 기본값 | 「미지정」·「없음」 같은 기본값 텍스트가 **반복 노출 안 됨** |
| A13 | 숫자 정렬 | 수치가 tabular로 **폭이 흔들리지 않음** |
| A14 | 상태 구분 | 완료 `●`와 검증 완료 `◉`가 **다른 모양** |

### B. 블라인드 식별 (5항목)

로고와 한글을 지우고 Linear·Cursor·Devin·Raycast 스크린샷 옆에 놓았을 때.

| # | 항목 | 통과 조건 |
|---|---|---|
| B1 | 축소되지 않음 | 이 표면이 답하는 것이 경쟁 도구가 «구조적으로 못 답하는» 질문임. **레이아웃이 무엇을 닮았는지로 판정하지 마십시오** — 상세 페이지·매니페스트·목록·트리 같은 검증된 형식은 목적에 맞으면 써도 됩니다. 실패는 「닮았다」가 아니라 「그것으로 끝난다」일 때입니다 |
| B2 | 3초 식별 | 처음 보는 사람이 3초 안에 「다른 종류의 도구다」를 알아챔 |
| B3 | 주인공 | 화면에서 가장 큰 영역이 **차별점**을 차지. 대화 스트림·diff·체크리스트가 주인공이면 실패 |
| B4 | 조직 | 사람 이름이 아니라 **역할과 소속**이 보임 |
| B5 | 판정 분리 | 실행자와 판정자가 **다른 주체**임이 화면에 드러남 |

### C. 학습가능성 (4항목)

| # | 항목 | 통과 조건 |
|---|---|---|
| C1 | 책임 | 이 화면만 보고 「누가 이 일을 책임지나」에 답할 수 있음 |
| C2 | 다음 행동 | 처음 보는 사람이 **다음에 무엇을 누를지** 앎 |
| C3 | 조작 관습 | 목록·선택·시트·승인/거절이 **흔한 문법**을 따름. 새 조작 발명 금지 |
| C4 | 시연 | 개념을 설명문이 아니라 **화면이 시연**함 |

### 판정 규칙

- **A·B·C 모두 통과해야 AAA입니다.** 하나라도 실패면 실패입니다.
- 후하게 주지 마십시오. **의심스러우면 실패입니다.**
- 실패 항목마다 **스크린샷 좌표나 구체적 요소**를 지목하십시오. 「전반적으로 밀도가 아쉽다」는 금지입니다 — 고칠 수 없습니다.
- 「B3 주인공」을 통과시키려면 **가장 큰 영역이 무엇인지 먼저 적고** 그것이 차별점인지 판정하십시오.

## 5. 금지 사항

- 도메인에 없는 값을 화면에 지어내기. **없으면 비우십시오.** 진단에서 지어낸 표현 37건이 나왔습니다.
- 계약이 `unknown`으로 주는 값을 좁히지 않고 렌더하기. 화면 경계에서 좁히고 형태가 안 맞으면 버리십시오.
- 하드코딩 hex. 반드시 토큰.
- 새 조작 문법 발명. 정보 구조는 새롭게, **조작은 흔하게.**

### 헌법 7절을 오해하지 마십시오 — 이것은 «스타일» 금지가 아닙니다

헌법 298행은 *"Massion을 다음 중 하나로 **축소하지 않습니다**"* 라고 씁니다: 채팅 앱 · Agent 런처 · IDE · PM SaaS · 정적 조직도 뷰어 · 단순 승인 수신함 · Extension Marketplace · VoltAgent 설정 UI · Web 래퍼.

이것은 **제품 범위** 진술이지 시각 어휘 금지가 아닙니다. 판정 기준은 «무엇을 닮았나»가 아니라 «무엇으로 축소되었나»입니다.

| 금지되는 것 | 금지되지 «않는» 것 |
|---|---|
| 확장 표면의 목적이 «탐색과 설치»로 끝나는 것 | 상세 페이지·권한 매니페스트·출처 표기 같은 UI 어휘를 쓰는 것 |
| 대화가 정본이 되는 것 | 대화 스트림을 화면에 두는 것 |
| 조직도가 정적 그림에 그치는 것 | 트리·노드·계층 시각화를 쓰는 것 |
| 완료를 체크리스트 소진으로 정의하는 것 | 체크리스트 형태를 쓰는 것 |

**목적에 맞으면 어떤 UI 어휘든 쓰십시오.** 검증된 패턴을 피하려고 낯선 조작을 발명하면 학습 부담만 늘어납니다(위 「조작은 흔하게」와 같은 원칙입니다).

예를 들어 확장 표면에서 권한 매니페스트는 「이 확장이 조직에 무엇을 부여하나」를 가장 명확히 보여주는 형식일 수 있습니다. 그때 문제는 매니페스트를 «쓴 것»이 아니라, 그 화면이 부여된 역량이 조직에서 실제로 무엇을 하는지로 이어지지 «않는 것»입니다.
