# Retained local document source and exact retrieval

KNW-01 and ADR0001 require document/evidence relationships and change impact. Above PR37 `731a09a137c6504c60efd2b1dee9caae4e0a8358`, the owner can paste an approved local plain-text source into a Mission, find its latest version and read an exact historical version before using its ID/version in the existing relation/impact flow. This supplies bounded source capture, not general document ingestion or verified truth.

`POST /missions/:id/documents` accepts exactly `commandId`, `expectedRevision` and `document:{id,version,title,content,source}`. IDs use `document:` followed by 1–64 ASCII alphanumeric/underscore/hyphen characters, beginning alphanumeric. A new ID starts at v1; each new version advances by one. Title is nonblank ≤200 UTF-16 units, source ≤2000, content well-formed and nonblank ≤16 KiB UTF-8. At most100 total retained document versions and1 MiB content bytes per Mission. Caller author/hash/MIME/path/URL/grants are rejected. The owner-only domain transition binds author and SHA-256 over exact UTF-8 content; no content normalization occurs. Versions append atomically; no earlier title/source/content/hash/author or Work/Record/relation changes. There is no filesystem/network fetch or executable parser.

Original CAS/feed, frozen caller input, durable fingerprint/receipt and idempotency apply. Same command replays without another version, changed identity content conflicts and concurrent owner writes retain one outcome. Portable validation checks fields/content hash/contiguous history/bounds and replays `capture-document`; recomputed or altered snapshot metadata cannot substitute for its original transition. Restores are inert and contain the text directly in the journal, requiring no new artifact path.

`GET /missions/:id/documents?query=...` reads one authoritative Mission snapshot with optional feed guard. The nonblank ≤200 UTF-16 unit query is literal and case-sensitive; only title/content of each document's latest version are searched. No regex, embedding, rank or relevance inference. Response identifies Mission/revision/feed/cursor/query, totalMatches, limit20 and up to20 matching exact identities/titles/sources/authors/hashes/excerpts. If there are more matches, narrow the query; no silent all-results claim. Mission storage is bounded; this aggregate scan does not establish indexed graph/search scalability.

`GET /missions/:id/document?id=...&version=...&sha256=...` selects an exact historical version and UTF-8 content hash. Unique strict query fields, positive safe version and lowercase SHA-256 are required. Missing version returns404 and mismatching hash409; corrupt stored document history fails503. No latest-version/content fallback or new command. The UI verifies all original fields, response Mission/feed/revision and content byte/hash binding. Reads cancel or discard late replies after selection, snapshot, Mission or connection changes. A same-snapshot reconnect clears the old controller and requires deliberate new retrieval.

The Workbench stores source input in Mission-private page memory, retaining its original CAS/feed through conflict/failure/refresh. Review deliberately rebases after comparison; cancel clears only the private draft. Pending/unknown writes lock duplicate save/review/cancel/switch; existing durable pending receipt recovery never repeats POST. Reload persists only nonsensitive command identity. Exact confirmed submitted values clear; later private edits and moved focus remain. Search and historical selection are read-only, with literal text rendering. Search results can open the exact original; reference ID/version remains visible for existing owner relationship authoring and explicit native impact inspection.

Updating a document never invalidates acceptance or rewrites an old Record/relationship. Existing inferred/owner provenance is not promoted to verified truth. No automatic relation, scheduling, model input/memory injection, provider call, external account/permission, merge or deployment. File/URL/mail/Drive collection, rich document/code parsing, retrieval relevance, indexed storage, automatic invalidation and production authentication remain open.

A separate [owner-selected local UTF-8 file draft](owner-file-document-draft.md) can now replace private pasted content/source after explicit preview and Use. Browser-local file access is distinct from server filesystem access; the server still receives only the existing reviewed document fields. Raw-file and normalized/edited document hashes have separate meanings.
