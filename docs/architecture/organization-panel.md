# Exact owner organization responsibility editing

The Workbench now exposes PR35's existing [organization revision API/domain](organization-revisions.md). Select an exact stored organization revision to inspect its author, reason and fixed executor/verifier role requirements. A historical version can be the source of a new draft; it is never modified. Select “New responsibility definitions” deliberately to begin blank definitions. The new organization version is derived from the reviewed current history, independently of the aggregate CAS revision.

Edit the two required responsibility texts and provide a new reason. The GUI fixes existing capability identifiers (`text-output` and `independent-text-review`); it accepts neither staffing actors, models nor grants. Owner-declared requirements are not measured capability. Save uses the normal ProductService/HTTP route, never execution. Existing Work/Records keep their original organization pin; the Work evidence panel shows the original snapshot or explicitly explains an unbound legacy Work. Newly admitted normal Work pins the committed current organization.

Each Mission's private selected source, edited values, original feed/aggregate revision and source contents remain independent across refresh, failure and Mission switches. Changed state does not silently advance a dirty draft. A known stale draft sends no POST until explicit current-state review; a change racing after review is rejected by the server's original CAS and is not retried. “Review draft against current revision” retains original source/edits and deliberately derives the next version from current history. Unavailable or changed source must be selected again. “Cancel private responsibility draft” clears only this private selection/values, preserving unrelated Work drafts and durable state.

Pending and unknown command markers use the existing shared browser write barrier. Saves, source changes, review/cancel and new mutations remain locked. Exact matching receipt confirmation settles only unchanged submitted values; later private input is retained. The fresh selection receives focus when a confirmed save clears the draft; another intentional focus move is preserved. A replaced database feed clears old confirmation messages and submissions; retained private data does not grant writes against an unavailable source.

“Check pending command receipt” retries only existing durable event reads. It performs no POST, model invocation or repeated save, and missing receipts leave writes locked. After reload the existing nonsensitive marker resumes read-only reconciliation; private editor text is held in page memory, not persisted across page reload. While event reads fail, Load / refresh still reads the snapshot; receipt confirmation remains necessary to unlock writes. Restored markers can belong to any pending Mission command, so the control is labeled generically and does not infer organization success from a snapshot. A fresh user action needs explicit source/current-state review.

No server/domain API or responsibility schema changed in this increment. The [scoped acceptance evidence](../acceptance/organization-panel-evidence.md) distinguishes supporting DOM/network injection from actual native normal CLI/browser/store behavior. Broader UI/platform/assistive-technology coverage, departments/membership, semantic staffing/reuse, measured capability, organization Growth and production authentication remain open.
