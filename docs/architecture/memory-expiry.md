# Owner-declared explicit memory expiry

Approved bounded MEM-01 increment above Draft #68 `5514c1a9710761d9411e5eb655d8a6d55f8bd060`. The owner reviews/cancels/declares a deadline for one exact currently effective same-Mission explicit memory ID/version/memoryVersionHash, reason, and UTC deadline. Immutable declarations have the same history bounds as conflict declarations. One deadline per exact version; no editing, withdrawal, automatic retirement, deletion, execution, learned-memory policy or new authority.

At or after the deadline, a separately submitted new Work is rejected while that exact version remains effective. The owner can use existing retirement to exclude it, then deliberately admit a new Work. Old Work pins, input hashes, Attempts, Records, unknown effects and Run preflight remain unchanged. New versions do not inherit an old version's expiry.

The Application samples its host UTC clock after operation identity readback and revision validation. An immutable `observedAt` event context accompanies expiry declaration and admission in a Mission with expiry history. The command fingerprint excludes this server-generated context: original command replay returns its receipt before sampling a new clock; caller-supplied context is rejected. Pure domain replay and portable validation use the recorded event observation, never the restore host's clock. Mission state retains a nondecreasing observation watermark; observations below it or unavailable/invalid observations reject. Declaration requires a future canonical UTC deadline (`YYYY-MM-DDTHH:mm:ss.sssZ`). Host clock observation is bounded local evidence, not an externally trusted clock: undetectable clock rollback across a restart is not claimed solved. No background timer or write on load/restart.

The normal UI presents exact original, version hash, UTC deadline, reason, revision and feed, with Review/Cancel/Declare. Private drafts and original reviews survive stale/unknown/late receipts and Mission switching; reviews invalidate on edits/revision/feed/epoch change. No command on Review or Cancel. Normal POST `/missions/:id/memory-expiry` accepts command identity, revision, declaration identity, exact reference, deadline and reason only.

Acceptance covers deadline boundary, host rollback watermark, immutable command replay after expiry/restart/restore, rejected admission without journal mutation, old Work/Record preservation, exact version/hash/authority/fields/bounds, CAS, normal CLI/headless keyboard, unknown/wrong-feed/late/private draft guards, and independent review. No real model calls, merge/deployment, paid resources or account changes.
