# One-shot provider dispatch claims

Above PR43, the minimum WRK-01/EFF-01/GOV-01/RUN-01 prerequisite for a later worker is explicit provider call ownership. The configured executor/verifier now records a `claim-provider-dispatch` between its effect intent and adapter call. The same atomic Mission CAS and operation identity bind a unique claim ID, original run/host/dispatch, assigned actor/model/config, exact canonical bounded request hash and claimed time before the run deadline. This is admission evidence, not a receipt that an external invocation occurred.

Only a fresh `committed` claim result allows this caller to attempt the adapter. A replayed/conflicting result or lost acknowledgment does not invoke, retry or reclaim; the original pending intent/claim and reserved output budget remain inspectable. A second registered claimant cannot overwrite a claim, even with a new command ID. Local registry membership and original host identity must match before this runtime claims. Immediately after the claim it reads current active Work and checks exact retained claim and request hash. Other-host cancellation/quarantine before this boundary prevents a zero-start call. Exact assigned actor plus claim ID are required for the subsequent receipt.

The existing PR43 commit-call admission/deadline fence remains. A transaction already admitted to Store, a final database read and a remote invocation are not a distributed atomic transaction. If another host commits quarantine after the final active read, the already allowed call attempt may still happen. Its late receipt/output cannot change quarantined or expired Work. A dedicated regression proves this limitation; claim is never presented as remote stop proof.

Legacy effects and Records have no inferred/backfilled claim. New optional effect metadata is copied into the accepted Record receipt checksum. Exact claim shape, run ownership, authorization, assignment, task, model, target and claim uniqueness are checked by semantic portable lineage, original accepted artifact reads and causal prerequisite binding. The read-only run-ownership API and existing literal Work ownership evidence display retained claims, including pending/unknown states; they do not expose editing or recovery grants.

The new pre-claim deadline test exposed an existing portable-lineage omission: deadline-converted pending effects were receipt-free unknown but the validator recognized only owner quarantine. Receipt-free unknown now requires the exact validated deadline/owner closure pending IDs. Deadline-converted effects reject fabricated receipts; original unknown receipts cannot disappear; unbound unknown/pending effects are rejected. Later owner quarantine preserves this deadline provenance.

Actual owned host-kill tests include before and after claim commit, alongside six prior boundaries. Restart retains the original claim, unknown handling decision, reservation and no-replay classification. There is no queue, scheduler, lease/expiry/reclaim, automatic recovery, external repeated action or production authentication. Controlled adapters and loopback mocks establish the contract without real-model claims.
