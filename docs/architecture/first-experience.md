# First experience (E7)

## Intent and boundaries

Reuse the subscription CLI provider identities, bounded argv-only runner, connection catalog, conversation command and member admission truth. Detect login kind with the official CLIs' local status commands; discard raw output, email and account metadata. Presence does not establish validity, model availability, permission or a verified provider call. Detection never reads credential files or enrolls a connection, changes a manifest, selects models or widens live-execution authority.

The first empty conversation shows Hana's greeting and approved suggestions only after explicit login-detection metadata arrives. A database reset clears onboarding for that page lifetime; an empty replacement conversation never restarts it. The established conversation remains the first section and configured connections bypass sign-in. Selecting a suggestion opens the first Work picker. Only the owner's Assign action sends the selected request through the existing conversation command; merely rendering, selecting, deferring mail or asking again never runs anything. Mail deferral is a private, feed-bound browser preference; Gmail connection opens the existing Apps settings, whose actual installed connectors remain authoritative. No fictional Gmail authorization is added.

First launch without a detected subscription or configured connection shows provider buttons. An explicit click starts the corresponding official CLI login, which opens its own browser flow. The host accepts fixed provider IDs and a command identity only, coalesces overlapping starts, retains unknown outcomes for the host lifetime and never resends the same login operation. Host drain aborts and awaits pending login processes. Authentication consumes no model call. CLI output and secret values never enter UI, logs or storage. No desktop security settings change.

A newly admitted member's deterministic first greeting is projected from its durable admission into its first conversation view, with one stable message identity. Reads, restarts and duplicate admissions cannot add extra greetings. This host introduction is not a provider reply or a fabricated model turn; it creates no Work, grants or model call.

## Verification plan

Tests first: sanitized detection and failure states; overlapping/unknown login starts; empty versus established conversation routing; picker selection/defer/explicit submission; feed/thread changes and late responses; member greeting readback and admission replay. Run related tests and typecheck locally. Capture B1, B1-signin, B1-first, B1-first-calc, B1-first-later and B21-done in both themes and retain pairs under docs/acceptance/e7. CI owns the full suite and all contracts. No live authentication or paid inference is performed for verification.

## Limits

Installed CLI login state is separate from an authorized, model-pinned Representative route. Existing host manifest, live opt-in, connection adapters and owner settings continue to govern actual calls. Unsupported/missing CLIs and unknown status fail closed without credential entry in Massion.
