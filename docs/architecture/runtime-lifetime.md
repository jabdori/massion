# Bounded host-owned run lifetime

Above PR42, the configured bounded text runtime records an immutable host-session ID, unique dispatch ID, start and deadline in each new runtime admission. Host policy defaults to 120 seconds and allows at most 300 seconds. Existing authorization, role, input, output-token and CAS gates still apply. Optional metadata preserves legacy input hashes and Record checksums.

One atomic activation admits one dispatch. Same/different run retries, another runtime instance and a restarted host cannot reclaim or replay it. Local registry membership describes only this process's active dispatch. Closing a browser does not stop the host. `GET /missions/:id/run-ownership?work=ID` reads one exact snapshot/feed and exposes original ownership, current host identity, local activity, interruption and unresolved effect IDs. Old identity or a passed clock is not evidence that an external operation stopped. Replay permission remains false.

An abort-aware invocation boundary returns promptly even when an adapter ignores AbortSignal. Before invoking, cancellation/deadline produces zero calls and known zero usage. After invocation, interruption reports unknown usage/outcome, retains reservations and discards late output. Pure progression is checked after Application lookup/load immediately before the underlying store commit call. This fences **commit-call admission**, not the completion time of a transaction already admitted to the database. Acceptance already committed before deadline retains its original Record even if its acknowledgment arrives later. Non-success receipt observations can retain truthful uncertainty after local interruption; committed deadline closure fences all later progression and receipts.

The host representative records exact-run/dispatch `expire-runtime` after its declared deadline. Pending effects become receipt-free unknown, existing receipts remain original, reservations are held, unresolved measurement stays null, and Work is blocked without fabricated acceptance or remote stop proof. A stable command ID and exact operation lookup reconcile a lost closure acknowledgment; up to three definite CAS revision conflicts can retry metadata closure without repeating effects. Unresolved storage failure remains an admitted unsettled run.

Accepted Records retain original ownership in their checksum. Artifact reads, causal prerequisite binding and portable semantic journal validation check the optional original binding. Legacy records remain unchanged. Existing Work evidence renders ownership/interruption literally; there are no new editing controls. This is a bounded stop/ownership prerequisite, not a scheduler, lease, automatic reclaim/resume, durable worker, production authentication or real-provider stop guarantee.
