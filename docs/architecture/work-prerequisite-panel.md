# Exact owner prerequisite authoring

Purpose established before implementation: PR50 can review/start a causal sequence, but normal UI owners cannot create its prerequisite declarations. WRK-01/COL-01/KNW-01/SUR-01 and issue #4 require an inspectable path from user intent to independently accepted, version-bound outcome. This increment exposes the existing owner-only work-prerequisite API; it creates no new domain command, scheduler, permission or execution.

Owner selects an existing fresh consumer and exact same-Mission predecessor, supplies a bounded reason, and deliberately reviews current input/criteria/budget/Record evidence. Review computes the same canonical input/criteria hashes as the core and retains original Work objects, values, revision, feed and connection epoch. Changes invalidate Attach; explicit review captures the chosen originals again, never a different Work. Self/duplicate/cycle/cap checks are supporting client gates; the existing authoritative transition remains final. A predecessor can be pending; attaching runs nothing and consumer execution still requires its independently accepted Record. Pins are append-only; corrections require new Work.

Private drafts stay per Mission in page memory. Cancel sends no command. Existing nonsensitive pending command identity, durable receipt readback, CAS/feed rejection and no replay are reused. Confirmed exact pin clears only the submitted unchanged draft; late edits remain. Current Mission and moved focus survive late successful, rejected and unknown replies. Normal Mission navigation is disabled while a short write is busy; asynchronous context replacement is also fenced by tests. Reload restores no draft and never attaches or executes anything automatically. Other Work/Records/history and existing sequence semantics remain unchanged.

Acceptance: normal CLI + actual SurrealDB + isolated Chrome keyboard selects/reviews/cancels/attaches a pending predecessor, then explicitly runs first/consumer through PR50 to accepted Records with exact predecessor checksum. Verify restart grants0/no automatic calls; original unrelated Work/Record retained. Supporting HTTP/DOM tests exercise stale revision, self/cycle/duplicate, lost committed reply, receipt recovery, late edits/focus/Mission/feed, independent review and exact-head push/PR CI. Fixture providers are credential-free; this does not prove semantic quality, remote authentication, full scheduling/recovery or full issue #4/accessibility completion.
