# Bounded non-text accepted results

R-E / B10 adds static PDF and RGB PNG producers above the existing immutable artifact storage boundary. The producer never accepts its own output: executor publication, a distinct verifier, settled effects and the normal accept command remain required. No network, model invocation or acceptance is hidden inside a writer.

The supported subset is deliberately closed: one-page printable ASCII PDF (40 lines, 96 columns), and non-interlaced 8-bit RGB PNG (at most 512 by 512 pixels). Both have a 1 MiB encoded byte limit. Readers check the complete supported structure, exact SHA-256 and byte bounds; unsupported formats, active PDF content, SVG and HTML fail closed. This is not a general PDF/image importer.

Keep `readRecordArtifact` and `ArtifactReader.read` text-only. A separate `readBinaryRecordArtifact` accepts the same exact Record/version/hash/feed input and returns bounded base64 plus the original Record checksum, artifact identity and provenance. It shares the existing acceptance checks and rechecks the authoritative feed and Record after asynchronous IO. No path is returned or accepted from the caller.

Results retain the originating Representative segment and exact source turn. Binary previews check response identity, byte count and SHA-256 before setting an image/PDF source. Reset, a newer open, removed results and replaced feeds invalidate pending previews and clear displayed bytes. Text remains inert text content.

## Integration contract

- Construct `BinaryArtifactStore(join(textArtifacts.root, 'binary-results'))`. This root has its own binary ownership markers; do not initialize the text and binary stores in the same directory. The existing text markers, `:text` IDs, `.txt` paths, relocation inventory, `read()` return type and 32 KiB reader limit remain compatible.
- `producePdf(text)` and `producePng(width, height, rgbBytes)` return genuine file buffers. `write(workId, version, kind, bytes)` validates before publication. `readBytes(artifact)` and `snapshot(artifact)` revalidate the immutable storage boundary and complete supported binary structure.
- The normal runtime producer is integrated by the coordinating agent in `src/configured-runtime.ts`. Its executor envelope is exactly `{format:'massion-result/v1',kind:'application/pdf',text}` or `{format,kind:'image/png',width,height,pixels}`. Validate numeric RGB arrays before constructing `Uint8Array`; conversion must not silently wrap invalid numbers. Independent review checks the decoded file content against the pinned owner request and criteria; the envelope creates no execution authority.
- `binaryArtifactText(kind, bytes)` derives PDF text or `RGB WxH` plus exact pixel hex values from the validated file. It rejects review projections over 32 KiB. The independent verifier quotes that representation while binding the actual binary SHA-256. Reread and compare it before `snapshot()` and normal acceptance. This projection is review evidence, not text masquerading as a PDF or image.
- `ArtifactReader` retains `read(artifact):Promise<string>` and adds optional `readBytes(artifact):Promise<Uint8Array>`. A separate `BinaryArtifactReader` requires only `readBytes`. The default server composes its existing text reader with the binary store above; a missing binary reader fails with 503.
- Serve `GET /missions/:missionId/record-binary-artifact?work=...&record=...&version=...&sha256=...` through `readBinaryRecordArtifact`. Reuse the existing unique query field, identifier, version/hash, feed header and error validation. Its response retains exact Record/checksum/artifact/evidence identity and adds `encoding:'base64'`; `content` is canonical base64, and `byteLength` counts decoded bytes. No local path is returned.
- For conversation-backed Records, `source` is `{segment,turnId,memberId}` derived from the accepted Record's validated `assistantSource`, checked against current Work provenance. The panel compares all three source fields with the selected row, in addition to feed, Mission, Work, Record, version, hash and kind. Source-less accepted binary Records remain readable directly but cannot impersonate a conversation result.
- The panel renders verified PNG as an image. For the closed PDF subset, it decodes the static text from the hash-verified PDF bytes and draws an inert page, with an Original download link to those same bytes. Binary previews disable the text-only Original tab and hide text copying. The existing frame CSP stays unchanged; artifact contents never become HTML or script.
- No new copy keys are required. Controls reuse `ui.panel.preview`, `ui.panel.original`, `ui.panel.unavailable` and existing Results copy. The PDF fixture filename uses `sidebar.link.14`; the PNG filename is the approved B10 data example, `로고 시안 3종.png`.

## Genuine screen fixtures

The coordinating agent should call `await binaryScreenFixture(template)` from `scripts/ui-contracts/binary-fixture.ts` for B10. The helper also supports isolated B10-preview tests; the existing text-preview contract keeps its original fixture. It preserves existing text rows and interaction steps, then appends the meeting PDF and a PNG containing three drawn logo variants. Both retain the approved artboard's Representative assignment (`memberId:null`). Valid source messages, source turns, Work summaries and original conversation segment 1 remain consistent with the exact reader response.

Each new result is written to an owned temporary filesystem root and passed through `Application` assignment, effect receipt, artifact publication, distinct-verifier judgment, task settlement and acceptance. Base64 read bodies are captured using `readBinaryRecordArtifact`; all fixture feed envelopes use that actual store's feed. Temporary files are removed in `finally` after capture. These are fixture-class, deterministic test results; no live-provider evidence or external calls are claimed. The factory does not import test modules or change fixture JSON. Hooking the factory and removing the Non-text results allow-list entry belong to the coordinating agent.

## Verification and limits

Targeted RED→GREEN tests cover real PNG pixels and PDF cross-reference structure; active/malformed/mislabeled/oversized bytes; immutable and concurrent storage; exact accepted identities and independent verifier/effect/snapshot checks; source substitution; unavailable byte ports; authoritative feed/Record changes during IO; and late, removed, replaced or closed preview contexts. Existing text store/reader/panel and Results regression tests remain included. Fresh-process imports also guard the binary entry points against cyclic initialization.

Verification uses the explicitly selected Node v24.21.0 binary. Its `node:zlib.crc32` matches the standard `123456789` checksum `cbf43926`; the API is documented in [Node v24.19.0](https://nodejs.org/download/release/v24.19.0/docs/api/zlib.html#zlibcrc32data-value). The PNG closed subset follows the [W3C PNG specification](https://www.w3.org/TR/png-3/): signature, IHDR/IDAT/IEND, CRC, dimensions and bounded decompression are checked.

The integrated validation ledger and current screenshots are in [R-E acceptance evidence](../acceptance/R-E/README.md). Tests use mocks/fixtures only. Fresh-process import tests cover the module initialization boundary.

The legacy portable format remains text-only. `collectMissionArtifacts` explicitly rejects a Mission containing binary results instead of exporting a bundle that silently omits files; a regression test pins this refusal. Binary portable backup/restore needs its own format/version migration. General PDF imports, Unicode PDF fonts, JPEG/SVG/HTML, arbitrary pixel sizes, live providers and real-DB execution are outside this slice.

For a multi-step team, `open-room` carries canonical `artifactBase64` from a fresh immutable-file read. The retained room's artifact keeps those bytes as `base64`. Room construction and transcript validation bind both their actual SHA-256 and `binaryArtifactText(bytes)` to the projected content, including during deterministic reconstruction. Text rooms retain the original string-hash check and reject binary-proof fields. Producing, challenging and independent checking identities remain separate.
