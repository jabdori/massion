# MCP apps and connection cards (E5b)

This increment extends the existing apps aggregate, owner decisions, content hashes and drain-aware store. It does not change Settings or the Work pane. PR #111 (E5a) was open at implementation start, so native launching and secret storage remain injected host adapters: absence refuses, with no environment/file fallback. No new dependency or outside call is needed for tests.

## Contract

- A manifest may declare `kind: 'mcp'` and an `mcp` descriptor: a stdio launcher target or loopback HTTP URL, and a bounded canonical list of tools (name, description, input schema, read-only flag). Exactly one server host is declared; stdio uses `localhost`. Endpoint, kind and tool additions/changes widen the version and reuse the install/update decision. Tool removals narrow it. Scripts without a kind retain their existing hash and behavior.
- The host adapter owns protocol negotiation, list pagination, secret attachment and transport cleanup. The service validates the connected list before each call; additional/changed tools refuse until a separately offered version is approved. Reads/writes require the exact tool in the pinned permissions and contributions. Missing read-only flags mean writes. Tool output is bounded data, never instructions or acceptance.
- A fresh durable tool claim precedes invocation. Replayed/ambiguous claims never invoke. A timed-out read fails; an uncertain write is unknown, survives restart and is never sent again. Abort triggers cancellation/cleanup through the adapter. The host timeout is 180 seconds and its value is recorded in each claim. Requests have separate transport identities so cleanup cannot target another concurrent call. Wiring tools into Work execution and its exception projection remains a follow-up rather than bypassing Work admission.
- An optional connection slot makes the existing install card a connect card. A host-only masked form submits the token once. A durable owner claim contains only decision/command identity, never token bytes or their hash. The secret adapter writes by app/slot; the connected tool list is checked, then successful completion commits the original owner decision. An update with the same approved slot reuses it. Lost storage/completion responses leave the claim unknown and are not retried. Read projections contain metadata only. Drain/feed fences apply before the secret write and before the final commit.
- E5b explicitly opts into isolated app UI beyond ADR 0005’s deferred default. An MCP app may declare a page; its host adapter supplies bounded HTML as data. The client renders it only in a sandboxed `srcdoc` iframe without `allow-same-origin`, giving each document a unique opaque origin. Its CSP denies network, nested frames, objects, forms and base URLs; the only message types are `ready` and bounded `resize`, checked against the exact source window and opaque origin. No tool, secret, navigation or application command exists in that bridge. Scripts keep their host-rendered views. Remote app URL loading is not introduced.

## Verification

Tests first: install approval and overlapping identity replay; tool permission, version/list change, timeout and restart/no-resend; token sentinel in HTTP and all persisted state, unknown and drain; isolated iframe attributes and closed bridge. Existing app tests cover script behavior and journal lineage. UI checks exercise B24/B25 and connection states in both themes, with side-by-side reference pairs. Connection copy is projected from the Korean copy table; self-made install cards link to their exact source Work using the existing read path. Locally run changed tests and typecheck; CI owns the full suite/contracts under the owner's verification budget.

Protocol reference: https://modelcontextprotocol.io/specification/2026-07-28/server/tools (annotations remain untrusted; the host owns permission).
