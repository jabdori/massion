# Browser snapshot and ref targeting (R-U4)

## Design

The declared CSS-selector path stays for PR #162/#163 fixtures until the follow-up PR migrates them. This slice adds the replacement path: an accessibility-style snapshot of the live page whose element refs the member acts on, following the analysed reference apps (Paseo snapshot/ref/fingerprint model, Codex Desktop stale-error-with-fresh-state and per-session origin allow-list, Claude Desktop typed stale errors and password fields excluded from value exposure, Grok secret-as-alias).

Replaced for the new path: fixed single origin, pre-declared elements/facts, and element ids from host declarations. The snapshot adapter derives structure itself: visible, enabled, native actionable controls (link, button, textbox, password, checkbox, radio, combobox) each get a `@eN` ref in DOM order. ARIA-only widgets stay unlisted because the owned runtime keeps scripts disabled, so they have no behaviour to act on. Same-origin iframes stay unsupported this slice. Text blocks, title and page text stay suppressed on private-tainted sessions (any form control present), and field values never enter a snapshot; element names come from labels, aria-label, title, placeholder or text, never from a value, and a name containing a present field value is masked. Caps follow Paseo: 1,500 actionable candidates, 500 refs, 80,000 snapshot characters, with a truncation marker.

Refs expire three ways: a new snapshot replaces the whole ref map, navigation starts a new document generation and clears refs, and every act re-verifies the ref fingerprint (role, name, tagName, type; the mutable value is excluded). A stale ref fails with a typed `stale-ref` error carrying the fresh snapshot so the member can re-plan without another read. The existing EnvironmentActions ledger, owner gates, no-replay claims, run deadline bounds, private-taint persistence and origin-only history are unchanged.

Owner floor without declarations: submitting a form that contains password/card/private fields, a secret-slot fill, and the first navigation to a new origin each require an owner decision through the existing decision entry path. New-origin approval is an `approve` wait; the member can also raise a takeover (`authentication` | `captcha` | `other`) as a new owner-wait kind on the same ledger. Navigation outside approved origins is blocked at three layers: the adapter refuses the target, the deny proxy refuses connections to unapproved origins (dynamic CONNECT allow-list), and page-initiated redirects die at the proxy. Approved origins join the per-Work allow-list the proxy reads.

Actions: click, secret fill, select, key press, scroll, navigate/back/reload, and a bounded wait on text or URL. Click, key and scroll use trusted CDP input (the three-method `Input.*` whitelist the references use); fill and select use the page-side value setter with input/change events, which is framework-compatible and the only way to preserve secret handling at the adapter boundary. Before acting the adapter waits for actionability in one page task: visible, enabled, editable for fills, scrolled into view, stable across two geometry samples, and hit-tested at its centre. Dialogs follow the Paseo policy: alert accepted, confirm/prompt/beforeunload dismissed, each handled dialog reported in the next result (bounded).
