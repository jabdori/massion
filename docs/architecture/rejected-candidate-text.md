# Exact failed candidate inspection

Purpose selected before implementation above PR51 `dac58e809c46efad3ef2268b94df9437cbba7aef`: normal Workbench can display failed Assurance metadata but cannot read the rejected artifact bytes. This blocks the owner from understanding a rejected result before deciding a correction. WRK-01/ASR-01/SUR-01 and issue #4 require execution and acceptance to stay distinct and original evidence to remain inspectable. This bounded increment exposes settled failed text only; it does not implement another attempt, correction admission, quality judgment or recovery.

GET `/missions/:id/rejected-artifact` requires exact Work id, canonical full Work hash, artifact version/SHA-256, and optional feed identity. The configured artifact reader chooses the stored path; no caller path or filesystem fallback is accepted. Validate known settled effects/receipts/tasks/attempt, settled execution, original input/criteria/verdict, independent assignments, source/memory/organization/prerequisite pins and existing runtime/dispatch claims. Unknown, interrupted, recovered, cancelled, accepted or changed Work cannot be read. Recheck full Work and feed after asynchronous reading. Unrelated owner writes do not substitute the chosen evidence. Bound well-formed UTF-8 to 32KiB, independently hash bytes on host and browser, return original failed verdict and fixture/real-provider classification without accepting a Record or exposing artifact filesystem path.

Normal UI displays a failed-candidate disclosure and deliberate Read/Cancel. Text and verdict use literal textContent. Work/feed/Mission/connection changes discard stale results; cancel ignores late responses and restores keyboard focus only if it belonged to Cancel. No automatic read, retry or continuation on reload/restart. Reading does not clear an unknown command marker, submit writes or invoke a provider. Existing source/Record/receipt/history remain authoritative. Controls are scoped to the existing owner Workbench; this adds no account or execution authorization.

Acceptance: actual SurrealDB, normal CLI and isolated headless Chrome keyboard explicitly run a credential-free incorrect fixture, inspect its exact rejected bytes/failed verdict, cancel a held read, retain old Work/Record and journal, reload with empty text and restart with grants0/automatic calls0 while exact failed evidence remains readable. Supporting API/UI regressions cover changed bindings, wrong feed, unknown receipts, owner cancellation, tampered bytes, reply classification, unrelated writes and late Mission responses. Existing accepted Record reads remain a regression gate. Independent review and exact published-head push/PR CI are required.

Remote authentication/account authorization and actual model quality/usefulness cannot be proved by this fixture. Broad correction loops, scheduling/recovery, multi-device authentication, broader accessibility/platform testing and full issue #4 remain open. No live model calls, paid resources, permission changes, merge or deployment belong to this increment.
