# Read stored unresolved Work across Missions

The product charter explicitly preserves a global inbox. WRK-01/GOV-01 and issue #4 require durable responsibility and visible questions/blockers/uncertain outcomes after client or host interruption. PR62 discovers Mission identities; it does not locate the Work requiring inspection across those Missions. This bounded increment adds an explicit read-only unresolved Work inbox and opens the existing current Work evidence/control surface.

Inclusion is based only on stored facts: an open owner question, an unknown effect, a pending effect on cancelled/interrupted Work, failed/stale acceptance, or a stored execution blocker. Accepted Work without unresolved evidence is not included; cancellation never hides an unknown outcome. The inbox labels each exact fact rather than inferring priority, current provider readiness, external stop, semantic quality, approval or a permissible recovery action. No new state, command, role, grant, outcome, scheduler or automatic action is created.

One native read transaction returns at most 20 small Mission/Work identity/revision/title/state/count/blocker summaries in exact Mission/Work ID order with feed/cursor-bound explicit Next. No source, discussion, artifact or receipt bodies are projected. Writes between pages or another database reject rather than mix results. Refresh and Close are explicit; no periodic scan or automatic paging. Selecting an item uses the existing authoritative fresh Mission Load, then opens the exact existing Work evidence, whose current facts govern all later owner decisions. It never applies a mutation from inbox metadata.

Acceptance: open questions and known failed/stale/blocked Work appear across Missions; cancelled unknown/pending outcomes remain visible; resolved questions and accepted/cancelled settled Work do not falsely remain unresolved. Normal CLI restart and fresh headless browser keyboard can find and inspect original uncertain/blocked Work without a known Mission ID. Exact source/question/receipt/Record/journal preservation, no calls/writes, paired same-ID feeds, empty/multiple pages, changed cursor, late/closed/disconnected reads and a changed Work before selection are verified. Unsupported reader/corrupt metadata fails closed. Independent review, small Draft and exact-head CI complete the bounded path. Full action inbox, semantic prioritization, receipt reconciliation, execution recovery, authenticated remote clients and product completion remain open.

The response size is bounded; this native projection still scans retained aggregate metadata. Indexed projection and production load certification remain open. Query shape follows official [SELECT](https://surrealdb.com/docs/reference/query-language/statements/select) and [SPLIT](https://surrealdb.com/docs/reference/query-language/clauses/split) semantics; local native tests verify the pinned runtime.
