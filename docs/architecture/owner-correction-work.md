# Explicit fresh Work after a known rejection

Purpose selected before implementation above PR52 `732c84b40d47fdecdc2a1269628de4d0068fea6c`: exact rejected text is now inspectable, but normal owners lack a linked correction path that preserves the failed original. WRK-01/ASR-01/GOV-01/SUR-01 and issue #4 require rejected output → owner correction decision → independent verification of a distinct outcome. Existing `revise-work` deletes the old verdict and cannot cross runtime no-replay safely; this increment does not use it.

Extend existing owner admission with optional exact correction selection (original Work id/full hash/reason). The atomic domain transition requires an owner, known settled failed text with bound runtime input/criteria/artifact/verdict and settled tasks/effects/receipts. Unknown/interrupted/quarantined/cancelled/accepted/changed originals reject even if a caller recomputes the hash. Add only distinct fresh Work under existing current Mission/criteria/effective memory/organization admission semantics. Persist an owner decision pin containing original hashes/pathless artifact descriptor and reason. Bind it in the new Work input hash, executor/verifier task data, extension version @6 and accepted Record checksum. Original Work/artifact/verdict/receipts/claims/reservations/Records are never modified. This provenance is a historical admission decision, not a prerequisite that a rejected original must become accepted or a remote-stop certificate. Later origin changes do not rewrite the pin; portable journal replay validates it at its admission point.

Normal UI privately selects the exact known failed original, writes a distinct Work id/request/reason/budget, compares the original with current new Mission/criteria/memory/organization inputs and deliberately reviews then admits. Original sources, instructions and prerequisites are not automatically inherited; attach selected source/prerequisite pins explicitly with existing controls. Changed revision/feed/connection epoch/selection invalidate admission until review. Private cancel sends nothing. Existing write CAS, durable receipt confirmation, unknown marker and no replay apply; late successful/rejected/unknown responses retain current Mission and later edits. Reload/startup never recreates a draft, admits or runs correction. Admission makes zero calls; explicit connection selection/preflight/Run remains separate and independently verifies the new output.

Acceptance: actual DB + normal CLI + isolated Chrome keyboard deliberately starts incorrect credential-free fixture, retains rejected original, cancels a correction draft, admits reviewed new Work with calls0, then explicitly runs a controlled fixed output to a separate accepted Record with original provenance.
