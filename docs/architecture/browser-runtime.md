# Browser session and page snapshots (R-B)

## Ephemeral image boundary (lead decision, 2026-11-10)

A page image cannot be proven free of secrets: CSS geometry can encode a value without text or image resources. Images are therefore live presentation only. They are captured through CDP into process memory, never a screenshot file. Automatic downloads are denied in the owned browser context before navigation. A running Work may show them in its browser pane; images are never part of a command, journal, Record, artifact, portable backup, log, client persistent storage or ordinary acceptance/E2E evidence. The only exception is the dedicated synthetic-local acceptance screenshot path described below.

Only sanitized structural observations, keyed HMAC-SHA-256 image hashes and page-read telemetry persist. Every field is masked unless every nonempty semantic signal is explicitly benign; an unknown/conflicting label, name or autocomplete cannot borrow another signal’s exemption. Durable unmasked fields must carry an explicit benign label. Benign exemptions require explicit plain-text labeling. Referenced/nested/generated/hidden labels and unsupported ARIA alternatives fail closed; a name alone never grants an exemption. Supported textual metadata is checked together; NFKC normalization and removal of format/default-ignorable characters happen before both sensitive detection and benign exemptions. Reflected-secret matching applies NFKC and caseless canonicalization (including case expansions), and ignores Unicode format/default-ignorable separators. Grapheme-based start/end maps preserve original UTF-16 ranges even when compatibility expansion or combining characters change the normalized length. Unicode decimal digits fold to ASCII for matching; private alphanumeric codes also ignore bounded punctuation/symbol grouping, including common phone/number formatting. Literal matching remains in parallel so punctuation-only secrets are not lost. Known private values and their Unicode, case, digit and separator-normalized forms also match padded/unpadded Base64 and URL-safe forms, with up to eight standard nesting rounds bounded by the observed text length. Base64 and UTF-8 hex display candidates are also decoded before canonical comparison, so inserted separators or compatibility characters cannot evade matching in the reverse direction. Display compatibility/ignored-character normalization preserves Base64 case and source offsets; whitespace/punctuation-separated candidates enumerate each ambiguous alphabet symbol independently (at most 64 interpretations); larger ambiguous candidates are fully masked, and four quartet alignments also cover ordinary word wrappers. Matching masks the original candidate span. Encoded spans map back to the original source range; text size and decoding depth are bounded, excessive nesting is refused, and decoded percent encodings keep the existing fail-closed boundary. Private seed values also expand through bounded URI/Base64/hex decoding of valid UTF-8, re-splitting reserved and compatibility boundaries after each decode (eight rounds, 1,024 variants, 4,000 characters per value). Exact original private values are compared before lossy normalization; decoding preserves BOM characters. The same matcher runs before image capture and structural persistence. Standalone card/API-key patterns use the same digit/format normalization. Durable addresses contain only the origin. Navigation paths, credentials, query and fragment stay out of observations and commands; commands carry a random navigation identity unrelated to the URL. Exact request bindings remain in a bounded process-memory map, never the journal. Same-process retries reuse that identity; after restart or binding eviction, callers must read the retained observation instead of replaying capture. This avoids making low-entropy capability paths guessable from a public digest. URL components, including query names/values and fragment parts, are decoded to a fixed point (at most eight rounds) and re-split at every round on reserved URL delimiters, including colon, before reflected-text/field redaction. Compatibility forms of those boundaries are split too. Malformed escapes encountered during decoding and excessive nesting fail closed. Bounds, idempotency, current-feed/revision/input checks and drain admission remain enforced. Durable validation rejects image-bearing observations rather than accepting a legacy pixel payload. Percent-encoded text remaining after masking is refused before dispatch and during durable validation, including nested/compatibility forms; recognized private encodings are masked first, and ordinary pages displaying such encodings can therefore be unavailable rather than retained.

Image hashes use a fresh random 256-bit key held only by the browser service and erased on drain. The key is never exported, so stored hashes cannot verify guesses of low-entropy pixels; restart intentionally loses the ability to recompute old hashes. Legacy unkeyed image hashes are rejected. Public reference-fixture source hashes describe fixed repository inputs only and are separate from runtime image hashes.

The browser service owns a bounded in-memory image map, keyed by feed, Mission, Work and read identity. Images enter only after a confirmed observation commit and a fresh active-state check. Storage write invalidation drops images before a Work leaves execution `active`, changes inputs or is replaced; runtime deadlines, host drain and restart also drop them. A store without lifecycle notifications cannot retain images. Reads recheck authoritative state and the exact durable schema, refusing legacy image-bearing snapshots rather than reviving their pixels. Restart/replay cannot regenerate a screenshot as a side effect.

Only the live browser query merges the transient image into its response; responses use no-store headers. Other mission, Record, artifact and backup paths see structural data and hashes only. The pane clears its memory/DOM on authoritative state changes, disconnect, deadline or navigation. Inactive/restarted Work shows only sanitized structural metadata. In particular, B4 payment approval is `waiting`, so it uses the structural view; only actively executing B15 displays a live image.

The page pane keeps one tab strip and a domain-only pill, and B7 keeps page counts without replacing R-A named steps. Reference HTML/CSS is local and reproducible, but captured page PNGs are no longer assets or evidence. Test fixtures generate live images only in memory; evidence screenshots exclude the image element while assertions still inspect the live rendering.

## Verification

Exercise capture, active read, settle, acceptance/Record, artifact, portable backup and restart. Search serialized journal/backup/Record/artifact bytes for the image bytes/base64 and a CSS-drawn sentinel: none may persist, only the hash. Assert inactive/deadline/drain/feed-change paths cannot return images and reactivation cannot revive them. Verify live rendering headlessly without saving page pixels, then run related tests/typecheck and the extra authorized CI/Codex loop. No real site, payment, submission, tag or PR merge.

The optional real adapter still requires exact HTTPS origins and a fresh script-disabled headless session. Existing DOM masking and paint suppression are defense in depth, not a confidentiality proof. The live owner-visible image can contain CSS-drawn secrets; non-persistence is the enforced boundary.

## Exact network origin

Each local read starts an owned deny-only proxy before Chrome. Only the selected HTTPS scheme, hostname and effective port bypass it; implicit loopback bypass is removed. All other HTTP/CONNECT/Upgrade traffic is refused without forwarding, including parser-driven resources and redirects before DOM inspection. Wildcard/subdomain/bypass-list host patterns are rejected. The native network policy does not depend on renderer-script injection, and TLS certificate verification stays enabled. E2E reuses the same denial server with its separate, explicit loopback-only policy. The browser uses [Chromium's scheme/host/port proxy rules](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md).

The production-adapter regression uses local HTTPS fixtures and a test-only certificate wrapper: allowed page/CSS reads succeed, while other-port parser requests, redirects and HTTP on the HTTPS port reach no target connection. No page image is written by this probe.

## Page-card fallback and synthetic visual evidence (lead refinement)

The no-image page card keeps the domain pill, one page heading and a Korean non-retention notice. It shows at most three distinct bounded content excerpts (longer content before short navigation labels, retained in source order) and six distinct fields. Three or more fields already form the summary, so redundant page/navigation excerpts are omitted. Masked fields keep their label, mask marker and an explicit masked annotation together. Empty structure shows only the domain and notice. The same bounded structure serves the live image's accessible alternative and its load-error fallback. Recorded page titles, origins and timestamps appear as read evidence, independent of named worker procedures.

Only the dedicated synthetic visual fixture may retain acceptance screenshots containing a live page image. It serves repository-authored HTML on local HTTPS, reads through `localBrowserAdapter` in a real isolated headless browser, and grants that exact origin only in its test invocation. The fixture certificate bypass is confined to a temporary test CLI wrapper. No production configuration gains a test allowance. The same Work is captured active and after settlement, in both themes at desktop and 390px. No standalone page PNG, image-bearing journal/record/backup, or generic evidence exception is introduced. The adapter remains read-only: existing form values are observations, not evidence of filling, clicking or submission.
