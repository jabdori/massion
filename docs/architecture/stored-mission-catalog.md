# Find stored Missions from a fresh client

MIS-01/SUR-01 and the product-owned durable responsibility in ADR0001 require a fresh client to continue stored Mission/Work. The current normal Load form requires a known ID and remembers only one browser-local ID; there is no authoritative Mission discovery query. This bounded issue #4 continuation increment adds an explicitly requested, read-only stored Mission catalog and selection through the existing fresh Load path.

The normal CLI injects a SurrealDB catalog reader, as it already injects the native relationship reader. One read transaction returns the original feed/cursor and at most 20 stored Mission identity/revision/purpose/scope/version/Work-count summaries, ordered by exact aggregate ID. It does not read document/message/artifact bodies, initialize schema, write a projection, expose journal operations or create a lifecycle/authority state. Explicit Next retains the original feed/cursor; intervening writes or a replaced database reject paging rather than silently mixing pages. Refresh starts a new read; no periodic scan, automatic paging, task run or mutation is added.

Acceptance: a new browser with no remembered ID discovers stored Missions and deliberately loads one through normal CLI; original Work/questions/source/accepted Record or unknown receipts remain inspectable and unchanged. Empty, bounded multi-page, changed cursor, same-ID different database, late/aborted reads and stale selection fail truthfully. Selection uses a fresh authoritative Mission read and existing permission/write barriers; a catalog entry is neither a snapshot for mutations nor proof of execution readiness. Unsupported reader and malformed stored identity/protocol fail closed. Real DB, normal CLI/headless browser keyboard, independent source review, small Draft and exact-head CI are required. Original histories and failed evidence are preserved. No authentication/ACL, execution permission, model invocation, scheduler, merge or deployment is introduced. A global action inbox and full product operation remain open.
