# Bounded local Work admission capacity

RUN-01/WRK-01/GOV-01 above PR47 46d7bfb: the normal top-level connection manager currently starts arbitrarily many unrelated Work concurrently. Bound this development Work runtime to one distinct Mission/Work admission at a time, using existing in-memory owned-runtime tracking and existing pure Work admission/preflight conditions. No new durable Work state or command/schema is required.

Before implementation acceptance: reserve before asynchronous admission reads at the normal host boundary; share capacity across user choices/router instances/Missions. Capacity rejection returns a host_busy preflight diagnostic and existing blocked result without changing original Work/revision/journal/budget/run/outbox or performing adapter/factory dispatch. Keep precedence of original already-started/cancelled/revision/invalid state; same-Work contenders retain CAS/no-replay classification. An occupied slot is local bookkeeping, not proof a remote provider is still running or stopped. Release the exact in-memory admission when its promise settles (including definite rejection, cancellation, deadline, committed-ACK uncertainty); preserve original admitted unknown claim/receipt/reservation and never replay it. A later fresh Work requires a separate explicit owner run request; no stored queue, automatic retry, authorization grant or restored authority. Existing drain waits all tracked promises and fences new admissions.

Verify regression-first memory and actual DB two distinct Work boundary, synchronous reservation before held snapshot/activation acknowledgment, same Work contenders, cross-Mission/router/configured runtime paths, release after cancellation/deadline/error/success, no automatic starts after slot release, original unknown/accepted Record/conversation preservation, portable restore/restart with no granted replay. Actual normal Linux CLI + owned loopback provider demonstrates busy rejection and explicit later fresh admission only; restart must retain original claims/unknown reservations, restore no grants and not start rejected fresh Work automatically. Native browser reads existing preflight busy diagnostic without creating a queue or changing drafts. Use only controlled adapters and owned disposable DB/host/browser/mock resources.

This is one bounded normal Work runtime's local admission capacity, not a process-wide global lock across independently constructed services, distributed worker lease, remote concurrency limit, project budget aggregate, production scheduler/daemon/VM isolation, provider stop proof or complete recovery. Already invoked transactions and remote effects may finish. External model/account/permission/paidresource/merge/deploy changes remain excluded.
