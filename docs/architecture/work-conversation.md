# Durable owner Work conversation

Above PR44 `771f9d4332ad46f103e54ae3550e49904c1c2d2d`, a separate Mission conversation entity holds one bounded thread for an exact existing Work. This is the minimum durable discussion foundation for SUR-01/COL-01/GOV-01. Existing steering remains an execution instruction; ordinary discussion is distinct.

`append-work-message` and normal owner `POST /missions/:id/work-message` accept commandId, expectedRevision, workId, messageId, replyTo and literal text. The host binds registered owner identity, owner role, deterministic thread ID and next ordinal. A reply names an earlier message in the same thread. No edit/delete, assistant or Representative response, automatic execution input, grant, stop proof or replay permission is inferred. Discussion remains available on accepted, cancelled and unknown Work without changing any Work/Record/input/claim/budget bytes.

Limits: well-formed nonempty UTF-8 text at most4KiB; at most100 messages and256KiB serialized thread, at most100 threads and1MiB serialized Mission conversations. Strict shape, IDs, order, unique message IDs and original reply targets validate both transitions and imported journal snapshots. Bounds reject atomically.

ProductService freezes the caller command before asynchronous lookups. Existing aggregate CAS, durable command identity and feed barrier govern writes: only committed exact receipt clears the submitted draft; lost ACK reconciles without another POST. `GET /missions/:id/work-conversation?work=ID` reads one store snapshot, accepts optional exact feed header, returns revision/feed/cursor and original conversation or null, and performs no writes or calls. Malformed originals fail closed.

The Workbench keeps private drafts by Mission/Work in this open client, retaining literal text/reply and original reviewed revision/feed across refresh, conflict and host reconnect. A changed state/database requires deliberate review. A replaced feed clears previous confirmation/submission metadata while retaining the draft's original feed; definite rejection removes submission metadata. A late input event during snapshot loss updates only an already existing exact private draft. Success clears only the exact submitted draft object; later edits survive. Successful keyboard submission focuses the message input if Save becomes disabled, preserving deliberately moved focus. Private drafts are not persisted across page reload; stored conversation originals are.

Normal clients on the same owner-configured host share stored messages and replies. This does not complete authenticated remote clients, actual bot communication, model-assisted questions/decisions, shared model context, full conversation orchestration or overall AgentOS acceptance. General scheduler/recovery remains separate. [Evidence](../acceptance/work-conversation-evidence.md).
