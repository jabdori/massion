# Exact accepted text access

The owner can inspect a stored accepted UTF-8 text result through the same ProductService and loopback HTTP host as the workbench. `GET /missions/:id/record-artifact?work=ID&record=ID&version=N&sha256=HEX` binds the exact Work, Record, artifact version and SHA-256. An optional `X-Massion-Feed` rejects another database identity. Duplicate or extra query fields, including filesystem paths, are rejected.

The host resolves only the accepted Record descriptor through its configured artifact read port. It checks canonical Record checksum, settled execution/effects, pinned artifact/criteria/verdict/assignments/memory, distinct executor/verifier identity and artifact snapshot binding. The read port is the existing sealed TextArtifactStore in the normal CLI. The host independently checks well-formed UTF-8, nonempty content, at most 32768 bytes and raw SHA-256, then rechecks the database feed and exact Record after the asynchronous read. No caller path, latest-result substitution, initialization, execution or mutation occurs. A relocated restore can supply its explicit portable artifact resolver.

Successful responses contain content, byte length, original Record checksum/evidence class, exact artifact identity, criteria version, Mission revision and feed. Unknown Mission/Work is 404, stale identity/feed is 409, unsupported artifact kind is 422, and absent/unreadable/integrity-failed text is 503. Physical paths are not returned. The interface remains loopback-only without production authentication.

In accepted Work evidence, expand “Read exact accepted text” and deliberately read, cancel or retry. Returned bytes are hashed again in the browser and displayed as literal text. Each read has its own abort/sequence/context guards. Mission, feed or exact Record changes invalidate it; unrelated owner writes and their recovery markers are independent. A read neither accepts a new result nor upgrades fixture evidence into a real-provider quality verdict. Non-text artifacts remain unsupported.
