# Causal Work prerequisites

Work can explicitly require another same-Mission Work's accepted outcome before execution. This closes a WRK-01/COL-01/KNW-01 execution-control gap under ADR0001; existing provenance-bearing `depends-on` relations remain advisory declarations.

The owner submits `POST /missions/:id/work-prerequisite` with `commandId`, `expectedRevision`, `workId`, `prerequisiteId`, exact `criteriaHash`, exact `inputHash` and required `reason`. The host binds the owner identity and appends an immutable declaration only to fresh unstarted Work. Up to three distinct prerequisites are allowed; self/cycles and chains exceeding 32 Work depth are rejected. All targets must already exist in the same Mission. No update/remove or latest rebind is exposed; a changed target input requires deliberate new Work.

A declaration can precede prerequisite acceptance. Pure preflight reports `prerequisite_unavailable` without mutation or provider dispatch until the exact target inputs/criteria match and its independently accepted Record is available. Atomic runtime activation and each effect admission enforce the same gate; acceptance also checks it. CAS protects the preflight-to-activation boundary. No scheduler, automatic execution, resume/replay or permission grant is introduced.

At activation or first effect admission the consumer retains exact prerequisite Record ID/checksum, criteria version, artifact ID/version/SHA/kind and evidence class. Subsequent effects/acceptance validate the same descriptors and the transitive accepted chain. Target Work/Record criteria, artifact, verdict, receipts, assignments, source/organization/memory pins, task/attempt settlement and independent verifier are checked, including exact assignment organization versions. This is stored accepted evidence, not a new judgment or artifact-content read. Both bounded runtime roles receive descriptors as task reference data; consumers use extension `@5`. Prerequisite declarations enter `workInputHash`, while legacy hashes stay unchanged. The accepted consumer Record includes declarations and exact Record descriptors in its checksum.

Existing Work evidence displays literal owner decisions and retained descriptors; existing execution preflight exposes pending diagnostics. This increment has normal headless owner authoring, not a new GUI prerequisite editor. Exact accepted text inspection and portable semantic lineage validate prerequisite bindings before allowing access/restore. Pending and deliberately stale declarations remain inert portable history; corrupted captured evidence fails closed. Later Mission versions never replace fixed Work inputs or Records.

Deterministic independent adapters establish the causal contract without credentials. Useful autonomous decomposition, artifact consumption/planning, real-model quality, general scheduling/invalidation, remote authentication and GUI authoring remain open.
