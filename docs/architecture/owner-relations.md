# Exact owner-authored relationship records

KNW-01 and ADR0001 retain the links between Work, documents, files, functions and evidence. Above PR36 `ba734b2406e489a6cf766c7ed088b3fee883986c`, a normal owner can append an exact relationship and inspect its existing native impact. This supplies an authoring path to the stored knowledge model; it does not ingest or certify referenced entities.

`POST /missions/:id/relations` accepts only `commandId`, `expectedRevision` and `relation`. The relation has exactly `from`, `to`, `type`, `fromVersion`, `toVersion` and `provenance`. Types are `depends-on`, `evidenced-by` and `contains`. IDs and provenance are nonblank, well-formed Unicode strings of at most 2000 UTF-16 code units; versions are positive safe integers. The host owner actor dispatches `record-relation`; caller actor/grant/inferred/verification fields are rejected. The host appends `inferred:false`. Owner-authored provenance is a declaration, not independently verified truth, and versions do not prove that endpoint content exists.

The existing aggregate transaction, original expected revision, optional feed guard, frozen input, durable command fingerprint/receipt and idempotency rules apply. A competing revision rejects without retry. Identical command replay adds no relation; changed content under the same identity conflicts. A distinct intentional command may append another provenance entry, preserving the existing duplicate and inferred-entry semantics. Appending to an aggregate with 1000 or more relations rejects before mutation, matching the existing native impact bound. Trusted historical `relate` fixture/import semantics remain unchanged.

The Workbench keeps exact input and original revision/feed in Mission-private page memory. First-load read recovery binds the authoritative feed before rendering an initial draft. Refresh never silently rebases an existing draft; known stale state sends no POST. Review explicitly updates only draft revision/feed after comparison; cancellation clears only the private relation input. Pending or unknown writes block duplicate save, review, cancellation and Mission switch. The existing durable receipt recovery (including its organization-panel control) checks the pending command identity without replay. Only matching confirmed submitted values are cleared; later edits and moved focus remain. Reload persists nonsensitive recovery identity, not private provenance text. Replacement feeds clear obsolete confirmations but retain the old draft and require explicit review.

History renders provenance literally. An explicit existing `GET /missions/:id/impact?entity=...&version=...` reads the authoritative stored relations through SurrealDB native reverse multi-hop traversal. Exact versions, mixed types, inferred flags, duplicate provenance and Mission isolation retain their previous meaning. This read does not schedule Work, invalidate accepted Records or call models. Earlier Work, memory, organization and accepted Records are unchanged. Portable journal semantic replay recognizes the owner command and restores the exact original graph inertly.

Typed/indexed graph projections, endpoint ingestion and existence authority, search, general graph navigation, execution dependency scheduling, automatic invalidation and independent truth evaluation remain open. This feature does not establish production authentication, measured provider competence or general AgentOS completion.
