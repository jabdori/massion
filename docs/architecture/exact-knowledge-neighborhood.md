# Exact-version relationship neighborhood exploration

Above PR64 `11478ffc`, KNW-01 and ADR0001's relationship-centric product requirement (issue #4) need a normal knowledge exploration path. Existing owner relation history lists all edges; reverse impact reports potentially affected dependents. Neither lets an owner follow direct outgoing evidence/containment/dependency references and incoming declarations one exact version at a time. This increment supplies an explicit read-only neighborhood browser over the existing authoritative Relation contract.

No new endpoint/entity existence claim, inferred truth, graph mutation, role, grant, scheduler, readiness or invalidation policy. A node is an exact user-declared reference ID/version, including an absent or historical endpoint. An edge retains exact from/to/type/versions/provenance/inferred, original aggregate ordinal and duplicates; self-loop appears once with both directions. Clicking a displayed neighbor explicitly requests its exact version in the same Mission, never latest content or an automatic graph walk. Empty adjacency does not prove endpoint absence/existence. UI field round-trip is checked before querying a selected/neighbor identity; CR identifiers that browser textarea normalizes are explicitly unavailable here, with no changed identifier query. Original edge text/native API preserve them; ordinary LF references remain supported.

Native query reads feed and selected Mission relation metadata in one transaction, applies exact incoming/outgoing matching in DB, max20 rows +one page probe ordered by original ordinal. The existing max1000 relation bound applies, with no truncation for oversized aggregate. Only exact edge metadata is returned; no Work/document/artifact/receipt bodies. Explicit Next retains feed/globalcursor/Missionrevision/reference; intervening writes or replacement feed reject rather than mix pages. Unknown/corrupt/unsupported readers fail closed without JS fallback or initialization. This bounded aggregate scan is not a typed/indexed graph schema or production load certification.

UI explicitly selects an existing declared endpoint or enters an exact reference/version, then Read. Close cancels the read and result; no initial/periodic/automatic GET or neighbor paging. Reads/selection carry abort/sequence, current Mission/snapshot revision/feed/epoch, literal original endpoints and provenance; late response, edited reference (including ABA), changed Mission/feed/revision, old neighbor button or closed result cannot reinstall stale evidence. Existing unknown receipt write barrier remains untouched; this is read-only. Restarts require deliberate exploration again.

Acceptance: actual native DB mixed relation types, duplicate provenance, inferred owner distinctions, self-loop/cycles, old/new same-ID versions, incoming/outgoing, non-existent endpoint, max1000 and page boundaries, Mission isolation, changed cursor/feed, portable restore and original Work/Record/journal preservation. Normal CLI restart and fresh Chrome keyboard explicitly explores a stored original document/Work reference, pages and follows one original neighbor without commands/calls, with390/1280layouts. Supporting transport/UI malformed metadata/stale/late/closed/unknown receipt checks, independent review, small Draft and exact-head CI. General graph storage/search/semantic truth, automatic retrieval/invalidation/execution and authenticated remote clients remain open.

Native original ordinal projection uses the documented second-index argument of [array::map](https://surrealdb.com/docs/reference/query-language/functions/database-functions/array). Local pinned-runtime DB tests verify this query; it does not introduce a derived graph write model.
