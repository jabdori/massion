## Proof boundary for clearing a browser key

An unchanged revision alone cannot distinguish a rejected request from a request whose transaction has not yet committed. Clearing a dispatched unknown key on that read would discard its original identity. This correction clears keys only for an offline/proven-unsent command or explicit server rejection, and retains a visible checking state for a dispatched unknown outcome. The owner may reread; no unknown provider invocation is resent. This is the safe interpretation of GLM's pre-commit-failure request, rather than treating a stale read as a rollback receipt.
