# 지속형 알림 센터 설계

## 목적

독립된 `확인 필요` 제품 표면을 제거하고, 어느 표면에서나 접근 가능한 전역 `알림` 패널에 사람의 조치가 필요한 항목을 통합합니다. 현재 범위는 실제로 존재하는 대기 승인(Approval)이며, 근거 없는 범용 알림 도메인은 만들지 않습니다.

## 정보 구조

- 전역 사이드 레일의 `알림` 버튼은 표면 전환이 아니라 패널을 엽니다.
- 배지는 선택된 업무가 아닌 조직 전체의 미해결 승인 수를 표시합니다.
- 패널을 닫거나 항목을 읽어도 승인은 사라지지 않습니다.
- 승인·거절 또는 서버의 취소·만료로 상태가 해결됐을 때만 목록과 배지에서 제거됩니다.
- 각 항목은 사람이 읽는 제목과 이유를 먼저 보이고, 출처 업무와 감사 식별자를 뒤에 둡니다.
- 승인·거절은 패널 안에서 처리하며 별도 화면으로 이동시키지 않습니다.

## 데이터 흐름

데스크톱 루트가 `governance.approval.list(status: pending)` 결과를 전역 상태로 소유합니다. 최초 연결, 내구 이벤트 수신, 패널 열기, 승인 처리 뒤에 다시 읽습니다. 업무 상세의 로컬 승인 상태는 기존 동작을 유지하되 처리 뒤 전역 목록도 동기화합니다.

`ApprovalViewV1.workId`는 데스크톱 투영에서 버리지 않고 보존합니다. 현재 Work 색인에 제목이 있으면 제목을, 없으면 감사 가능한 Work 식별자를 표시합니다.

## 화면과 설정

- 주요 표면은 홈·업무·조직·개선·확장·설정 여섯 개입니다.
- `알림`은 표면과 별개인 전역 유틸리티입니다.
- 기존 `확인 필요`에 섞여 있던 실행 자율성은 `설정 > 실행 자율성`으로 이동합니다.
- 로딩·오류·빈 상태를 패널 내부에서 각각 표시합니다.

## 검증

집중 통합 테스트로 다음을 고정합니다.

1. 승인 없는 업무를 선택해도 전역 승인 배지가 유지됩니다.
2. `알림`은 현재 표면을 바꾸지 않고 패널을 열며, 닫았다 다시 열어도 미해결 항목이 남습니다.
3. 패널에서 승인하면 서버 명령이 호출되고 항목과 배지가 제거됩니다.
4. 실행 자율성은 알림이 아니라 설정에서 조회·변경됩니다.

기존 데스크톱 전체 테스트와 타입 검사로 주변 회귀를 확인합니다.
