# Massion 문서 지도

[English](README.md) | [한국어](README.ko.md)

## 상태를 기록하는 규칙

- 아키텍처 문서는 구성요소의 책임, 관계와 금지 경계를 설명합니다. `구현됨`, `완료`, 고정 테스트 수로 상태판을 만들지 않습니다.
- 제품 문서는 목표와 불변량을 설명합니다. 현재 코드에 맞추려고 제품 목적을 축소하지 않습니다.
- 설계와 계획은 작성 당시의 의도와 순서를 보존합니다. 오래된 체크박스나 Phase 문장을 최신 상태로 해석하지 않습니다.
- 검증 증거는 실행 날짜, 후보 SHA, 정확한 명령과 결과를 함께 기록합니다. 다른 커밋의 출시 근거로 재사용하지 않습니다.
- `완료`는 독립 검증을 통과한 Work의 도메인 상태 또는 후보 SHA에 결속된 검증 결과에만 사용합니다.

## 공통 용어

문서에서는 사람이 이해하는 의미를 먼저 쓰고 내부 용어를 괄호에 병기합니다.

| 의미 | 표기 | 설명 |
|---|---|---|
| 사용자가 맡긴 영속적인 일 | 업무(Work) | 요청, 실행, 승인, 산출물과 상태의 정본 |
| 실행 책임과 분리된 품질 판정 | 독립 검증(Assurance) | 완료를 허용하거나 차단하는 검증 |
| 결정과 결과를 보존하는 기록 | 기록(Records) | WorkRecord, ADR, 변경·운영 기록 |
| 검증된 경험으로 다음 버전을 바꾸는 과정 | 자가개선(Growth) | 제안, 평가, 채택, 효과와 되돌리기 |
| Workspace에서 얻은 코드·문서 관계 | 지식(Knowledge) | 인덱스, 검색, 관계와 인용 |
| 모델과 계정을 공급하는 외부 경계 | 제공자(Provider) | Codex, OpenAI 호환 API와 로컬 모델 등 |
| 에이전트 추론과 도구 실행 계층 | 실행 계층(Runtime) | Provider 호출, 재개, 취소와 사용량 |
| 제품 상태를 안전하게 시연하는 데이터 | 시연 데이터(fixture) | 실제 사용자 데이터나 출시 증거가 아닌 렌더링 입력 |

같은 문서 안에서 첫 정의 이후에는 영문 용어를 그대로 사용할 수 있습니다. 내부 식별자는 사람이 이해하는 의미 뒤에 둡니다.

## 역사 문서

`docs/phases/`, `docs/superpowers/plans/`와 `docs/evidence/`는 삭제하거나 현재형으로 일괄 수정하지 않습니다. 당시의 결정, 실패와 검증을 보존해야 하기 때문입니다. 현재 정본과 충돌할 때는 이 문서의 분류에 따라 제품 헌법, 아키텍처, 코드와 최신 SHA 결속 증거를 확인합니다.
